# AGENTS.md — AI-конструктор коммерческих предложений (КП)

## Общая информация

**Для кого:** сервисная компания (услуги, поддержка, аутсорс и т.п.).
**Цель продукта:** сократить подготовку КП с часов до минут. Менеджер заполняет бриф → ИИ собирает черновик КП по шаблону → человек проверяет и правит → выгрузка в PDF.

**Рекомендуемый стек:**
- Python 3.10+
- **Streamlit** (быстрый MVP, формы и редактирование из коробки) *или* **FastAPI** (если нужен отдельный API-слой). Для MVP предпочтителен Streamlit.
- ИИ: **GigaChat API** (Сбера) или **YandexGPT / Yandex AI Studio**. Выбор одной модели — конфигурируется, не зашивать жёстко.
- Генерация PDF: **reportlab**.
- Хранение данных: SQLite (достаточно для MVP) через `sqlite3` или SQLAlchemy.

## Пользователи и роли

- **Менеджер** — заполняет бриф, редактирует черновик КП, выгружает PDF.
- **Руководитель** — задаёт шаблон структуры КП и прайс услуг.

Роли в MVP можно реализовать простым переключатем роли в UI (жёсткая авторизация не требуется), но доступ к редактированию шаблона/прайса должен быть только у роли «Руководитель».

## Главный сценарий (definition of happy path)

1. Менеджер заполняет бриф: **клиент, задача, услуги, сроки, бюджет**.
2. Приложение проверяет обязательные поля (валидация до отправки в ИИ).
3. GigaChat / YandexGPT генерирует текст КП **по заданному шаблону структуры**.
4. Менеджер правит текст в редакторе и скачивает PDF, **идентичный отредактированной версии**.

## Состав MVP (scope)

- [x] Форма брифа с валидацией обязательных полей.
- [x] Шаблон структуры КП (редактируется руководителем).
- [x] Генерация текста ИИ по разделам шаблона.
- [x] Ручное редактирование черновика.
- [x] Экспорт в PDF (reportlab).
- [x] История КП (список сохранённых КП с датой и версией).
- [x] Прайс услуг (название, цена) — ведёт руководитель.

**Вне scope MVP:** множестенные согласования, отправка КП по почте, CRM-интеграции, шаблоны в DOCX, работа с несколькими организациями.

## Экраны (страницы Streamlit / маршруты)

1. **Бриф** — форма ввода + валидация обязательных полей.
2. **Черновик с редактором** — сгенерированный текст по разделам, свободное редактирование, повторная генерация.
3. **Предпросмотр и PDF** — рендер итогового вида и скачивание `.pdf`.
4. **История КП** — список сохранённых КП, открытие, версия, дата.
5. **Настройки (Руководитель)** — редактор шаблона структуры КП и прайса услуг.

## Модель данных

- **Бриф:** `id`, `клиент`, `задача`, `услуги` (список из прайса), `сроки`, `бюджет`, `дата создания`.
- **КП:** `id`, `бриф_id`, `текст` (по разделам), `версия`, `дата`, `статус черновик/финал`.
- **Прайс услуг:** `id`, `название`, `price`, `единица` (опционально), `активна`.
- **Шаблон КП:** `id`, `список разделов` (заголовок + инструкция/промпт-подсказка для модели), `активен`.
- **Логи промптов:** `id`, `timestamp`, `промпт`, `ответ`, `модель`, `ошибки` — **без персональных данных**.

## ИИ и интеграции (обязательная часть)

### Правила генерации

- Модель пишет текст КП **строго по разделам шаблона**: каждый раздел — отдельный запрос или один запрос со структурой разделов.
- **Цены подставляются из прайса кодом.** Модели запрещено их придумывать:
  - Перед генерацией в промпт передаются только актуальные цены выбранных услуг из прайса.
  - После генерации кодом проверяется, что в тексте нет «новых» чисел, похожих на цены, отсутствующих в прайсе (защита от галлюцинаций). Найденное — заменять на значение из прайса или на плейсхолдер «цена уточняется».
  - Если цена услуги отсутствует в прайсе/брифе — в КП выводится «цена уточняется», **ИИ не имеет права её генерировать**.
- Ответ модели парсится по разделам шаблона; непонятный/битый ответ — показать ошибку и предложить повторить, не теряя бриф.

### Безопасность ключей

- API-ключ хранится **только в переменной окружения** (`GIGACHAT_API_KEY` / `YANDEX_API_KEY`) или `.env`, который **не коммитится** (`.env` в `.gitignore`).
- Ключи не хардкодить в коде, не выводить в логи и UI.

### Логирование

- Логировать промпт и ответ модели для отладки.
- **В логи не попадают персональные данные** (имена контактов, телефоны, email): перед отправкой промпта в модель ПДн обезличиваются/исключаются из передаваемого контекста.
- Ретеншн логов ограничен, хранение локальное.

## Критерии готовности (DoD)

- [ ] PDF **совпадает** с отредактированной менеджером версией (без расхождений текста, кроме переносов строк).
- [ ] Модель **не выдумывает цены**: если цены нет в брифе/прайсе — в КП нет выдуманного числа.
- [ ] API-ключ защищён: только окружение/`.env`, файл не в репозитории.
- [ ] Валидация обязательных полей брифа до вызова ИИ.
- [ ] История КП сохраняется и открывается с сохранением версии и даты.
- [ ] Роль «Руководитель» редактирует шаблон и прайс; «Менеджер» — нет.

## Правила разработки для агентов

- Язык интерфейса и документации: **русский**.
- Не хардкодить API-ключи и URL модели — выносить в конфиг/окружение.
- Любая генерация цен — **только** из прайса через код (`src/price.py`), не через модель.
- PDF обязан корректно отображать **кириллицу**: стандартные шрифты reportlab её не поддерживают. Зарегистрировать TTF-шрифт с кириллицей (например, DejaVu Sans) через `reportlab.pdfbase.pdfmetrics.registerFont`, положив файлы `.ttf` в `assets/fonts/`.
- Перед добавлением новой зависимости — обновить `requirements.txt`.
- Тесты обязательны для: валидации брифа, guard-проверки цен, парсинга ответа модели, экспорта PDF.
- Не выходить за рамки MVP без явного согласования.
