# Отчёт-кейс: «AI-конструктор коммерческих предложений»

- **Продукт:** MVP для сервисных компаний — бриф → черновик КП от ИИ → ручная правка → PDF.
- **Стек:** Streamlit · YandexGPT / GigaChat · reportlab · SQLite.

---

## 1. Проблема и аудитория

**Проблема.** Сервисные компании (поддержка, аутсорс, услуги) готовят КП вручную: менеджер собирает текст, вставляет цены, оформляет PDF. Одна заявка занимает часы, цены часто «приблизительные», шаблоны — у каждого свои.

**Аудитория.** Две роли внутри компании:

- **Менеджер** — готовит КП: заполняет бриф, правит черновик, выгружает PDF.
- **Руководитель** — задаёт структуру КП и прайс услуг, контролирует процесс.

**Цель MVP:** сократить подготовку КП с часов до минут — бриф → черновик ИИ по шаблону → ручная правка → PDF.

## 2. Выбранный MVP

- **Стек:** Streamlit (интерфейс и формы), YandexGPT / GigaChat (конфигурируемый провайдер), reportlab (PDF с кириллицей), SQLite.
- **Сценарий:** менеджер → бриф с валидацией → ИИ генерирует по разделам шаблона → человек правит → PDF идентичен отредактированной версии.
- **Жёсткие правила:** цены в КП — только из прайса кодом (ИИ не имеет права придумывать), ключи API только в `.env`, логи без персональных данных.
- **За рамками:** согласования, почта, CRM, DOCX, мультитенантность — осознанно вырезано.

## 3. Что реализовано

| Блок | Результат |
|------|-----------|
| **Бриф** | Форма с валидацией обязательных полей (клиент, задача, услуги, сроки) до вызова ИИ; бюджет опционален |
| **Генерация** | ИИ пишет текст по разделам шаблона; цены и сроки подставляются кодом из прайса и брифа |
| **Guard-слой** | Выдуманные цены/сроки заменяются на «цена уточняется»; нет цены в прайсе → плейсхолдер; обезличивание ПДн в логах |
| **Редактор** | Пораздельное редактирование с сохранением правок, перегенерация отдельных разделов и всего КП |
| **PDF** | reportlab с кириллицей (DejaVu Sans / системные TTF), единый источник контента с предпросмотром |
| **История** | Все версии КП: дата, версия, статус черновик/финал, открытие сохранённых |
| **Настройки** | Прайс и шаблон структуры — только роль «Руководитель»; живая проверка подключения к ИИ |
| **Развёртывание** | Русская вкладка вместо англ. меню Deploy: шаблоны Docker/requirements/secrets без реальных ключей |
| **Оформление** | Тема «Изумрудный», мобильная адаптация (скролл таблиц, компактные отступы) |

## 4. Как проверялось

- **Тесты: 68 passed, 1 skipped** (пропущен только Docker-тест деплоя). Покрыты: валидация брифа, guard-проверка цен, парсинг ответа модели, логирование без ПДн, PDF.
- **Сквозной тест PDF:** текст из готового PDF извлекается (pypdf) и построчно сверяется с отредактированной версией.
- **Аудит по DoD:** подтверждены все 6 критериев — PDF = редактированная версия; цены не выдумываются; понятные ошибки API без потери брифа; ключ только в `.env` (grep по коду чист); обязательные поля блокируют генерацию; мобильная вёрстка.
- **Живая проверка:** рабочее подключение к YandexGPT (роль `ai.languageModels.user`), генерация, сохранение версий и PDF проверены на реальном сервере.

## 5. Что улучшить дальше

1. **Качество генерации** — дообучение промптов под стиль компании, «человеческий» тон, авто-итог бюджета.
2. **Рабочий процесс** — статусы согласования (черновик → финал → отправлен), комментарии руководителя.
3. **Интеграции** — отправка КП по email из приложения, экспорт в DOCX, подключение к CRM.
4. **Актуальный ИИ** — GigaChat как второй провайдер (ключ уже можно сгенерировать скриптом), выбор модели в настройках.
5. **Продукт** — git-репозиторий + CI (тесты на каждый коммит), чистка тестовых данных «ООО Тест», авторизация вместо переключателя ролей, проверка мобильной вёрстки на реальных устройствах.

## 6. Как в проекте применяется ИИ (внешний API)

### 6.1. Какая задача у ИИ

ИИ в проекте решает **одну задачу**: по заполненному брифу пишет текст коммерческого предложения строго по разделам шаблона. Всё, что касается денег, сроков и фактов, он делать не вправе.

**Провайдеры** (выбор в `.env`, `AI_PROVIDER=yandex | gigachat`):

- **YandexGPT** (`yandexgpt-lite`) — активен по умолчанию;
- **GigaChat** (`GigaChat:latest`) — альтернатива, подключается переключением конфигурации.

Оба спрятаны за интерфейсом `LLMProvider.complete(system_prompt, user_prompt, …)` (`src/ai/base.py`) — код страниц не знает, какой провайдер работает.

**Как строится запрос** (`src/ai/prompts.py`):

- **Системный промпт** жёстко запрещает модели: придумывать цены, суммы, сроки, даты, контакты, телефоны, e-mail, реквизиты. Тон — деловой, на русском.
- **Пользовательский промпт** — бриф (клиент, задача, сроки, бюджет) + выбранные услуги из прайса (цены «только для справки, в текст не включать») + разделы шаблона с инструкциями руководителя.

**Что происходит после ответа** (оркестрация `src/ai/service.py` + guard-слой `src/ai/guard.py`):

1. Ответ разбирается по разделам шаблона (`parse_sections`); битый/пустой/неполный ответ — ошибка.
2. Цены в КП добавляются **только кодом из прайса** (`src/price.py`); любую выдуманную моделью сумму guard заменяет на «цена уточняется» (`sanitize_prices`).
3. Придуманные сроки/даты заменяются сроком из брифа или «срок уточняется» (`ensure_deadline` / `sanitize_dates_in_text`).
4. Каждый вызов логируется (`src/logging_util.py`) — промпт, ответ, длительность, ошибка; **без персональных данных** (промпт заранее обезличивается через `depersonalize`). Ретеншн логов — 30 дней.

Дополнительно есть **живая проверка подключения** (`src/ai/check.py`): короткий тестовый запрос «Напиши слово привет» по кнопке на странице Настройки — результат показывается без каких-либо ключей.

### 6.2. Что происходит при ошибке

Все сбои превращаются в типизированные ошибки (`src/ai/errors.py`):

| Сценарий | Ошибка | Пример сообщения в UI |
|---|---|---|
| Ключи не заданы / неверный провайдер | `AIConfigError` | «Не настроен ИИ-провайдер. Скопируйте .env.example в .env…» |
| Неверный/истёкший ключ (401/403) | `AIAuthError` | «Ошибка авторизации YandexGPT (HTTP 403).» |
| Превышены лимиты (429) | `AIRateLimitError` | «Превышен лимит запросов… Попробуйте через минуту.» |
| Таймаут / нет сети | `AITimeoutError` / `AINetworkError` | «ИИ-сервис не ответил за отведённое время…» / «Нет соединения…» |
| Битый/неполный ответ модели | `AIResponseError` | «Модель вернула пустой ответ. Повторите генерацию.» |

**В интерфейс попадает только `friendly_message()`** — человеко-понятный текст без технических деталей, HTTP-тел и следов ключей (проверено тестом `test_friendly_message_never_leaks_detail`).

**Бриф не теряется**: при ошибке ИИ `pages/1_Бриф.py` показывает сообщение и сохраняет заполненный бриф в сессию (`set_brief(brief)` до `st.stop()`) — при повторном заходе форма предзаполнена, повторная генерация не требует перепечатывания. Ошибка блокирует запись в БД (бриф сохраняется только после успешной генерации).

До вызова ИИ срабатывают две защитные проверки: валидация обязательных полей брифа и проверка, что провайдер настроен.

### 6.3. Как защищён ключ

1. **Ключи хранятся только в `.env` / переменных окружения** (`src/config.py`, `python-dotenv`). Захардкоженных ключей в коде нет — grep по `src/`, `pages/`, `tests/` чист; в `src/deploy.py` только плейсхолдеры для шаблонов развёртывания.
2. **Файлы секретов не попадают в git**: `.env`, `.env.*` и `data/` — в `.gitignore`.
3. **Ключ не попадает в клиентский код**: всё выполняется на сервере Streamlit; в браузер уходит только результат генерации, ключ — исключительно в HTTPS-запросах к API провайдера (не в HTML/JS).
4. **Ключ нигде не светится**: сообщения об ошибках формируются без значений ключей; логи промптов обезличиваются ещё до записи; страница «Проверка подключения» не показывает ключ и детали ошибки.
5. **Развёртывание без секретов**: вкладка «Развёртывание» генерирует `secrets.toml`/шаблоны с плейсхолдерами — реальные значения добавляются на сервере развёртывания отдельно.

## Приложение: структура проекта (кратко)

```
fin_proekt/
├── app.py                  # Streamlit entrypoint
├── src/
│   ├── brief.py            # модель/валидация брифа
│   ├── proposal.py         # модель КП, версии, история
│   ├── template.py         # шаблон структуры КП
│   ├── price.py            # прайс услуг (единственный источник цен)
│   ├── ai/
│   │   ├── base.py         # абстракция LLM-провайдера
│   │   ├── gigachat.py     # клиент GigaChat
│   │   ├── yandex.py       # клиент YandexGPT
│   │   ├── guard.py        # цены/сроки, обезличивание ПДн, парсинг
│   │   ├── errors.py       # типизированные ошибки + friendly_message
│   │   ├── check.py        # живая проверка подключения
│   │   └── prompts.py      # системный и пользовательский промпты
│   ├── pdf_export.py       # генерация PDF (reportlab, кириллица)
│   ├── app_state.py        # роли, session_state, мобильный CSS
│   ├── storage.py          # SQLite
│   ├── deploy.py           # шаблоны для развёртывания
│   └── logging_util.py     # логи вызовов ИИ без ПДн
├── pages/                  # страницы Streamlit (1–5)
├── tests/                  # 68 тестов (pytest) + 1 пропущенный (Docker)
└── docs/theme_preview/     # превью тем оформления
```
