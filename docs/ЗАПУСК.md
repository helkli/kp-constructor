# 🚀 Запуск проекта локально

Полная инструкция: от клонирования репозитория до готового КП в PDF.
Проверено на **Windows + Python 3.9**; команды для macOS/Linux отмечены отдельно.

> Короткий путь: `copy .env.example .env` → заполнить ключ → `pip install -r requirements.txt` → `python -m streamlit run app.py`.
> Подробности — ниже.

---

## 1. Что требуется

| Требование | Подробности |
|------------|-------------|
| **Python 3.9 или новее** | Проект проверен на 3.9.4 (x64). Проверка: `python --version` |
| **Ключ ИИ-сервиса** | YandexGPT **или** GigaChat — см. раздел 4 |
| **Интернет** | Нужен и при установке пакетов, и при каждой генерации КП |
| **Свободный порт 8501** | Занятый порт — не проблема, см. раздел 8 |
| Около 150 МБ на диске | Зависимости + шрифты для PDF (`assets/fonts`) |

Ключи в код не вставляются никогда — только в файл `.env` (он вне git).

---

## 2. Получить проект

```bash
git clone https://github.com/helkli/kp-constructor.git
cd kp-constructor
```

Или скачать ZIP: **Code → Download ZIP** и распаковать. Без git тоже работает —
в проекте нет шагов, требующих истории.

## 3. Виртуальное окружение и зависимости

Виртуальное окружение изолирует проект от системного Python.

### Windows (PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

> Если PowerShell ругается на политику запуска скриптов:
> `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` — действует только
> в текущем окне терминала.

### Windows (cmd)

```bat
python -m venv .venv
.venv\Scripts\activate.bat
```

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Признак успеха: в начале строки терминала появится `(.venv)`.

### Установка пакетов

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Устанавливаются: `streamlit`, `reportlab`, `requests`, `python-dotenv`, `pytest`, `pypdf`.

## 4. Ключ ИИ-сервиса

Провайдер выбирается переменной `AI_PROVIDER` в `.env`. Нужно заполнить **одну** пару ключей.

### Вариант A · YandexGPT (рекомендуется)

1. Зайти на [console.yandex.cloud](https://console.yandex.cloud).
   Нужен **платёжный аккаунт** — без него генерация не оплачивается.
2. **Создать каталог** → открыть «Обзор» → скопировать **ID каталога** вида `b1g…`
   → это `YANDEX_FOLDER_ID`.
3. **Сервисные аккаунты** → создать (например `robot-kp`) → выдать ему на каталог роль
   **`ai.languageModels.user`**. Без роли ключ будет работать, но запросы вернут 403.
4. В этом сервисном аккаунте: **Ключи API → Создать API-ключ**. Ключ показывают
   **один раз** — сразу сохраните его. Это `YANDEX_API_KEY`.
5. Модель по умолчанию — `yandexgpt-lite`. Если на каталоге доступна другая,
   укажите её в `YANDEX_MODEL`.

```env
AI_PROVIDER=yandex
YANDEX_API_KEY=AQVN...ваш_ключ...
YANDEX_FOLDER_ID=b1g...ваш_каталог...
YANDEX_MODEL=yandexgpt-lite
AI_TIMEOUT=60
```

### Вариант B · GigaChat

1. Зарегистрироваться на [developers.sberbank.ru](https://developers.sberbank.ru)
   и создать приложение → получить **Client ID** и **Client Secret**.
2. Ключ проекта — это `base64("client_id:client_secret")`. Собрать его и сразу
   записать в `.env` можно штатным скриптом:

```bash
python scripts/make_gigachat_key.py <client_id> <client_secret> --write-env
```

```env
AI_PROVIDER=gigachat
GIGACHAT_API_KEY=ваш_base64_ключ
AI_TIMEOUT=60
```

### Создать файл `.env`

```powershell
copy .env.example .env          # Windows
```

```bash
cp .env.example .env            # macOS / Linux
```

Правила заполнения:

- значения **без кавычек** и без пробелов вокруг `=`;
- файл в кодировке **UTF-8**, одна строка — одна переменная;
- `AI_TIMEOUT` — не более 60 секунд (ограничение по ТЗ);
- ключ хранится **только** в `.env`: файл уже исключён из git.

## 5. Запуск приложения

```bash
python -m streamlit run app.py
```

Далее:

1. Браузер откроет **http://localhost:8501** (если не откроется — скопируйте адрес вручную).
2. В **сайдбаре** видно статус: `ИИ: yandex — ключ настроен`, таймаут и переключатель ролей.
3. Тема — «Изумрудная» (задана в `.streamlit/config.toml`).

Полезные ключи запуска:

| Ключ | Зачем |
|------|-------|
| `--server.port 8502` | другой порт, если 8501 занят |
| `--server.headless true` | не открывать браузер автоматически |
| `--server.address 0.0.0.0` | доступ с других устройств в сети (осторожно: файловый доступ только по чтению, но приложение не имеет встроенной авторизации) |

Остановить приложение — **Ctrl+C** в терминале.

Быстрая проверка, что сервер отвечает: <http://localhost:8501/_stcore/health> → `ok`.

### Windows: если Python не один или его нет в PATH

На этой машине проект запускается через лаунчер `py -3.9`, потому что установлено
несколько версий Python, а команда `python` в терминале может отсутствовать или
указывать на **другую** версию. В этом случае замените `python` на `py -3.9` **во всех**
командах — и при создании окружения, и при запуске:

```powershell
# создание окружения именно на 3.9
py -3.9 -m venv .venv
.\.venv\Scripts\Activate.ps1

# запуск
py -3.9 -m streamlit run app.py
```

| Симптом | Что значит |
|---------|-----------|
| `python : имя "python" не распознано` | Python не в PATH — используйте `py -3.9` |
| `py -3.9 : модуль не найден` | Python 3.9 не установлен: `py --list` покажет доступные версии, нужен 3.9 или новее |
| `ModuleNotFoundError: streamlit` после активации `.venv` | активировано окружение, созданное **другой** версией Python — пересоздайте его командой `py -3.9 -m venv .venv` |
| `ModuleNotFoundError: dotenv` | не установлены зависимости: `py -3.9 -m pip install -r requirements.txt` |

Полезно проверить, что venv создан на нужной версии:

```powershell
py -3.9 -c "import sys; print(sys.executable, sys.version)"
```

В пути активированного окружения должен быть `...\.venv\Scripts\python.exe` — это
подтверждает, что `py -3.9` и терминал работают с одним и тем же интерпретатором.

Те же замены применимы к проверке ИИ и тестам:

```powershell
py -3.9 scripts/test_ai.py
py -3.9 -m pytest -q
```

## 6. Проверить, что ИИ живой

**Из терминала** (самый быстрый способ):

```bash
python scripts/test_ai.py
```

Успех выглядит так:

```
AI_PROVIDER = YandexGPT
OK: подключение работает
Ответ модели: Привет.
Провайдер: YandexGPT, модель: yandexgpt-lite
```

**Из приложения:** страница **«5 · Настройки»** → переключить роль на **Руководитель**
в сайдбаре → вкладка **«🤖 Подключение к ИИ»** → кнопка **«Проверить подключение»**.

Модульно: тесты проекта (`68 passed, 1 skipped`; пропускается только тест развёртывания в Docker):

```bash
python -m pytest -q
```

## 7. Первый запуск: демо-данные (по желанию)

Чтобы сразу увидеть заполненные разделы, «Историю» и предпросмотр:

```bash
python scripts/seed_demo.py
```

> ⚠️ Скрипт **очищает все брифы и КП** в базе и создаёт три демонстрационных.
> Прайс услуг и шаблон структуры не трогает.

Полный сценарий вручную: **«1 · Бриф»** → заполнить клиента, задачу, услуги, сроки →
**«Сгенерировать черновик»** → **«2 · Черновик»** (правка по разделам, ⟳ перегенерация) →
**«3 · Предпросмотр»** → **«Скачать PDF»** → **«4 · История»**.

## 9. Где что хранится

| Путь | Что внутри | В git? |
|------|-----------|--------|
| `.env` | Ключи API | ❌ никогда |
| `data/app.db` | SQLite: прайс, брифы, КП и версии, логи вызовов ИИ | ❌ нет |
| `assets/fonts/` | TTF-шрифт с кириллицей для PDF | ✅ да |
| `.streamlit/config.toml` | Тема и скрытие кнопки Deploy | ✅ да |

**Сброс базы:** остановить приложение → удалить `data/app.db` → запустить снова.
База создастся заново, с прайсом услуг и шаблоном по умолчанию.

## 10. Если что-то пошло не так

Проблемы с версией Python и `PATH` на Windows разобраны отдельно в
[разделе 5](#windows-если-python-не-один-или-его-нет-в-path) — начните с него,
если `python` не запускается или `ModuleNotFoundError` появляется после активации `.venv`.

| Что видите | Причина | Что делать |
|------------|---------|-----------|
| «Не настроен ИИ-провайдер…» | нет `.env` или ключа | `copy .env.example .env`, заполнить ключ, **перезапустить** приложение |
| «Ошибка авторизации (HTTP 401/403)» | неверный ключ либо нет роли `ai.languageModels.user` на каталоге | пересоздать ключ, проверить роль сервисного аккаунта |
| «Превышены лимиты запросов (HTTP 429)» | лимит провайдера | подождать минуту и повторить |
| «не ответил за отведённое время» | превышен `AI_TIMEOUT` | проверить сеть, повторить; `AI_TIMEOUT` — максимум 60 секунд |
| «Нет соединения с …» | нет интернета, VPN, корпоративный прокси | проверить доступ к `llm.api.cloud.yandex.net` / `gigachat.devices.sberbank.ru` |
| `Address already in use` | порт 8501 занят | `python -m streamlit run app.py --server.port 8502` |
| `ModuleNotFoundError: streamlit` | не активировано venv или не установлены пакеты | активировать `.venv` и повторить `pip install -r requirements.txt` |
| В консоли «кракозябры» вместо кириллицы | кодировка консоли Windows (cp1251) | это только вывод в терминал; в приложении и PDF всё в UTF-8. Чистый вывод: `$env:PYTHONUTF8=1` |
| Правки `src/*.py` не видны в приложении | Streamlit не переимпортирует модули | перезапустить процесс (Ctrl+C → запуск заново), затем обновить страницу браузера (Ctrl+F5) |
| В PDF вместо букв пустые места | не скопирована папка `assets/fonts` | проверить наличие `.ttf` в `assets/fonts` |
| Вопрос по логике работы | — | [ТЗ.md](../ТЗ.md) и [AGENTS.md](../AGENTS.md) |
